# عين سين

مسابقة عربية لفريقين ومقدم إلزامي، بواجهة React وTypeScript على GitHub Pages، وخادم Cloudflare Workers مع D1 وDurable Objects.

## المباراة

يختار المقدم ٦ فئات من أصل ٣٠، أو يستخدم زر قرعة الفئات، ثم ينشئ جلسة. يدخل المشاركون بالاسم ورمز الغرفة أو QR، ويعيّن المقدم القائدين. يستطيع المقدم المشاركة كقائد أيضاً. القرعة تحدد الفريق الذي يبدأ؛ القائد وحده يجيب ويضغط البزر ويستخدم المساعدات. شاشة العرض اختيارية.

لوحة المباراة **١٨ خانة**: لكل فئة سؤال واحد بـ٢٠٠، وآخر بـ٤٠٠، وآخر بـ٦٠٠. اختيار السؤال والبديل والفاصل حتمي بالبذرة المحفوظة. وقت الإجابة قابل للتخصيص بمؤشر من ٢٠ إلى ١٢٠ ثانية من إعدادات المقدم قبل بدء المباراة (الافتراضي ٢٠ ثانية)، وبزر الخطف ٧ ثوان ثم إجابة الخطف ٧ ثوان، والفاصل ٥ ثوان. المضاعفة قبل كشف السؤال فقط. وسائل المساعدة ومراقبة المقدم بين الأسئلة محفوظة.

## البيانات والأيقونات

`src/data.json` ونسخته المنشورة `public/data.json`: ٣٠ فئة و٤٨٠ سؤالاً. النص والإجابة مطابقان للملف المرفق. النقاط أعيد توزيعها بعد الموافقة إلى ٦ أسئلة بـ٢٠٠ و٥ بـ٤٠٠ و٥ بـ٦٠٠ لكل فئة لتوفير الاختيار والبديل. `sourcePoints` يحفظ الصعوبة الأصلية. لا تعرض المباراة أكثر من ثلاثة أسئلة لكل فئة.

الملف الأصلي لا يحتوي خيارات أو تلميحات أو ملفات وسائط. أضيفت خيارات بأربعة أجوبة للحفاظ على «شيل خيارين»، وتلميح حرفي مولّد موسوم بـ`hintSource`. `content/source-questions.json` و`content/source-categories.md` يحفظان المصدر. `scripts/content/choices.py` يضم بدائل الأسئلة؛ `scripts/content/build.py` يعيد بناء البيانات وقص الأيقونات (Python + Pillow).

`content/art/sheet-1.png` إلى `sheet-3.png` هي الصور الرئيسية الثلاث. `public/categories/c01.png` إلى `c30.png` قصاصات PNG دون إعادة تحجيم، وأبعاد ومصادر القص في `content/art/crop-manifest.json`.

## ما أُجّل لتبسيط النسخة

الفئات البصرية والسمعية تعمل بأسئلة الوصف النصي الموجودة في المصدر؛ لم تضاف صور أسئلة أو تسجيلات صوتية غير موجودة. أُجلت آليات مقارنة الصور، تكبير الصور، الاستماع للمقاطع، التحكيم بـ«أقرب تخمين»، والمخاطرة الخاصة؛ جميع الفئات تستخدم نظام الأسئلة والخيارات والنقاط الموحد حالياً. لا توجد موسيقى.

## المراجعة التحريرية

حُفظت الأسئلة والإجابات حرفياً، بما فيها الإجابات متعددة الاحتمالات. بعض النصوص تحتاج مراجعة معلوماتية مستقلة لاحقاً، ومنها فئة المخاطرة الأسئلة ٤ و٨ و١٥، ولغز يوم الأسبوع وفئة النوستالجيا متعددة الإجابات. لا يُعد نقل النص كما هو تحققاً من صحته. يمكن لمسؤول البنك تعطيل سؤال أثناء المراجعة، مع ضرورة بقاء بدائل كافية في كل مستوى.

بوابة الأسئلة متاحة للجميع للتصفح والبحث والتصدير. تعديل البنك محمي لمسؤول الأسئلة عبر Cloudflare Access. تغيير البنك لا يغير لقطة أسئلة مباراة جديدة بدأت بالفعل.

## التطوير والتحقق

Node.js 24:

```sh
npm ci
npm run check
npm test
npm run integration
npm run build
```

`npm run integration` يبني Worker ثم ينفذ الترحيلات على D1 محلي ويختبر الغرف والبزر والحفظ وWebSocket والصلاحيات. لا توجد إجابات البنك داخل حزمة واجهة اللعب؛ metadata فقط تُستورد في المتصفح.

## النشر

المصدر في `project/` داخل المستودع، والواجهة المبنية في جذره. Workflow `Deploy Cloudflare and connect game` يطبق الترحيلات وينشر الخادم ويثبت عنوان الخدمة الفعلي في `config.json`، ثم يعيد بناء GitHub Pages. يستخدم السر الموجود `CLOUDFLARE_API_TOKEN`؛ لا يوضع في الواجهة. تُجزأ بيانات SQL إلى تعليمات قصيرة لتوافق حد D1 لحجم التعليمة، ثم يُستبدل البنك بعد اكتمال التجميع.

الغرف تنتهي بعد ٢٤ ساعة من آخر إجراء. Durable Objects تسلسل الأوامر وتدير البزر والمؤقتات؛ D1 تحفظ الغرف والفرق والأعضاء وسجل النقاط والأحداث. مفاتيح الجلسات تخزن في D1 كبصمات SHA-256.

التصميم عربي RTL ومتجاوب للجوال الأفقي والأجهزة المطوية. الشعاران بخلفية شفافة، وتسلسل حركات البداية والمباراة والدور والنهاية محفوظ. الخط Cairo مرخص SIL OFL في `licenses/`.

يمكن لكل مستخدم إيقاف الحركات والأنيميشن من الزر أعلى الصفحة. يُحفظ التفضيل على الجهاز، وتُتجاوز شاشات حركات البداية والدور والنهاية دون تعطيل اللعب.
